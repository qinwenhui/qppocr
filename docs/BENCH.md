**工具**：`tools/bench_pipeline.py`。方法论沿用 migration-bench 的结论：
这台机器单次跑分波动可达 ±27%，**每轮 rust/cpp 交替先后（偶数轮 rust 先、
奇数轮 cpp 先）、5 轮 + 1 轮 warmup（丢弃）、每图 bench=3 取该轮最好**，

## 分解定位（这轮差距 1.34x 从哪来）

QPPOCR_PROF=1（对标 C++ LEAN_PROF2）+ det 单模型交错直跑：

| 层 | rust warm | cpp | 结论 |
|---|---|---|---|
| executor 开销 | 0.3 ms | 1.1 ms | **排除**（我们更好） |
| det 单模型 kernel | 36.0 ms | 30.5 ms | **1.18x，主要差距** |
| 冷启动（首跑） | 43 ms | 31 ms | 池 256 MB 后从 5ms 差缩到部分缓解 |

per-shape（warm）：

| shape | rust | cpp | 备注 |
|---|---|---|---|
| Conv 64→16 k3x3 g1 | 3.4 | 3.9 | **反超**（im2col 修复后） |
| Conv 32→64 k1x1 ×3 | 1.3 | 1.5 | 反超 |
| Conv 32→32 k3x3 g32 ×3 (dw) | 3.1 | 2.2 | 1.4x ← 最大单项 |
| Mul ×13 | 2.7→**1.4** | 1.4 | 本轮已修（见下） |
| Add ×23 | 1.7 | 1.1 | 1.5x |
| Resize ×6 | 1.2 | 1.2 | 持平 |
| Relu ×20 | 0.9 | 0.5 | 1.8x（fork 开销占比） |

## 本轮顺手修的两个问题

1. **池上限 64 MB→256 MB**：det 的 concat/中间张量 95 MB 级，64 MB
   上限把最大块全部挤出池（冷跑差 5ms 的主因）。
2. **binary_op 分配路径漏接 AVX2**（Mul 13 个节点全标量）：
   快路径 1（单元素）、2（run）、同形三条全部接上；对拍发现并修正了
   向量 run 的双重偏移 bug（bsrc 已偏移又 add(ib)）。修后 Mul 2.7→1.4ms。

## 剩余差距的已知构成（1.18x kernel 内）

- depthwise（g32/g48/g64）在引擎上下文 1.4x，micro-bench 持平——
  「单次执行 vs 反复热跑」的上下文差异，怀疑是指令缓存/分支预测器
  冷启动，C++ 单一大编译单元在此占优。候选手段：conv 分支按
  group/shape 特化内联。
- Add/Relu 等小算子的 fork 次数（56 次/图）固定开销。
