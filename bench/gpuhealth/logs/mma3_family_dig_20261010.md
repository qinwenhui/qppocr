# 挖 `n_conv8_mma3` 家族 —— 装载/MMA 比值这条杠杆，以及一次被漂移骗到的差点误判（2026-10-10）

任务 #34。家族 = `n_conv8_mma3`(64 宽) + `n_conv8_mma3_n32`(32 宽)，medium det 上
**23.98 ms / 11 条 = 设备端 20%**，从未挖过。

**一句话**：n32 那条实例化**卡在装载发射槽**上（base/hoist = **2.1×**，64 宽那条只有
1.35×），处方是把它的 simdgroup 从 8 个减到 4 个（每 sg 瓦片 16×16 → 32×16，
每 MMA 装载数 **1.00 → 0.75**）——探针 **1.26×**、真计划 **1.26~1.30×**，已落地。
同一个手法搬到 64 宽（0.75 → 0.50）**实测 0.35×，被寄存器压力打死**，一刀切掉。
端到端只有 **det −1.95 ms（中位，6/8 轮为负）≈ 1%**——n32 在 det 里本来就是少数。

---

## 0. 判据：每 MMA 的装载数

一个 simdgroup 的瓦片 M 行 × N 列，每走一步 K=8 装 `M/8` 个 A 分片 + `N/8` 个 B
分片，换 `(M/8)(N/8)` 条 MMA。于是

    每 MMA 的装载数 = (M+N)/8 ÷ (MN/64) = 8(M+N)/(MN)

| 瓦片 | 每 sg 格数 | 比值 | 谁用 |
|---|---|---|---|
| 16×16 | 256 | **1.00** | n32 现状（8 组 / 256 线程） |
| 16×32 | 512 | 0.75 | n64 现状（8 组 / 256 线程） |
| 32×16 | 512 | 0.75 | **n32 候选**（4 组 / 128 线程，同一块 64×32 瓦片） |
| 32×32 | 1024 | 0.50 | n64 候选（4 组 / 128 线程）—— **实测崩** |

比值只是**假设**，瓶颈是量出来的。探针（`probe_m3.metal`，4 条 arm + 2 个网格档）：

| arm | 干了什么 | 读法 |
|---|---|---|
| `base` | 生产副本（含真尾声） | 基准 |
| `small` | 地址掩到 `& 0xFF`、stride 8 ⇒ 只剩 256 B 常驻 L1 | base ≫ small ⇒ 是**流量/延迟** |
| `hoist` | 全部 `simdgroup_load` 挪出两层循环 | base ≫ hoist（≈ small） ⇒ 卡在**装载发射槽** |
| `noepi` | 只去掉 bias/act/残差/写回 | 量尾声值多少 |
| `_notail` | 网格不带尾块 | 尾块整块值多少 |

跑法：`cargo test --release -p qppocr-metal conv8_mma3_load_attribution -- --nocapture`
（原始输出 `m3_attr_20261010.txt`）。

## 1. 探针读数（medium det 四个真实形状）

| 形状 | NCOLS | base/hoist | base/small | 尾块纯冗余 | **候选 half** |
|---|---|---|---|---|---|
| Conv.121 240x216 c256→64 k3 | 64 | 1.36× | 1.15× | 1.14 ms (15.9%) | 0.345×（崩） |
| Conv.3 240x216 c128→64 k3 | 64 | 1.44× | 1.20× | 0.57 ms (14.9%) | 0.374×（崩） |
| Conv.111 240x216 c32→32 k7 | 32 | **2.13×** | 1.24× | 0.70 ms (18.1%) | **1.265×** |
| Conv.114 240x216 c32→32 k5 | 32 | **2.10×** | 1.26× | 0.34 ms (16.7%) | **1.261×** |

三条结论：

1. **n32 卡在装载发射槽**（`hoist ≪ small`，2.1×）⇒ 抬瓦片值得做。落地 **1.26×**。
2. **n64 没有可抬的余地**：它的 base/hoist 只有 1.36×（七成时间不在装载上），
   而它的 0.75 已经等于 n32 的目标档。
3. **0.50 那一档别试**：实测 0.35×。累加器分片 8 → 16（每 lane 16 → 32 个 f32
   寄存器）直接把内核打崩。这就是 `n_conv_dw` 那条教训的形状
   （[[probe-wins-dont-transfer-to-production]]：探针说「没用」可信，「有用」要复核）。
   这一档是**探针划掉的**，不是推理划掉的——比值表看上去它最美。

顺带：尾块「算完就丢」的纯冗余合计 **2.75 ms（14.9~18.1%）**，此前已论证过没有
替代方案（搬给 `n_conv8_edge` 要 2.9 ms，只省 1.30 ms）。

## 2. 落地：`n_conv8_mma3_n32` 改 128 线程 / 4 个 simdgroup

改动两面：

* `shaders/n_conv8_mma3.metal`：`mma3_body<NCOLS>` → `<NCOLS, NSG>`，
  `RPSG = 64/(NSG/2)`、`NR = RPSG/8`、尾声步长 = `NSG*32` 由 NSG 派生。
  瓦片映射 / 覆盖矩形 / 尾块锚点与掩码 / 参数 / `ost` 尺寸**一字不改**。
* `pipeline.rs`：新增按内核名的线程组尺寸表 `threads_per_group()`，
  `n_conv8_mma3_n32 → 128`，其余恒 256。

⚠️ **新耦合面**：内核按 `tid>>5` 认 simdgroup，宿主给多了线程就会有线程认领到
不存在的 sg、去写 `ost` 的界外行——**静默算错**。兜底是 `conv8_mma3_matches_cpu`
（14 例，其中 5 例 N32，含 stride2 与奇尾），它走的是**生产派发路径**
（`ks.dispatch`，即含这张表）。

**数值零变化**：K 的求和顺序没动，只是哪个 lane 算哪个输出变了。
CPU 对拍 14/14 过，最大误差 4.17e-7（原来的量级）。

## 3. 端到端：只有 ~1%，而且差点被漂移骗到

先做的是**顺次**对比（跑完 new 再跑 old 的 `QPPOCR_GPU_KERNEL_PROF`）：
new 的每个内核都比 old 快 ~20%，看起来大获全胜。**但没动过的内核也在变快**
（`n_conv_dw` 35.22 → 28.03、`n_conv8` 11.03 → 8.13）⇒ 那次对比量的是**机器漂移**，
不是改动。今天这台机器的漂移幅度实测有 ~25%。

改判据：**同一次 run 内，拿没动过的兄弟内核当尺子**：

| 同 run 之比 | new | old | 归一化 |
|---|---|---|---|
| n32 单条最大 ÷ mma3(64) 单条最大 | 0.407 | 0.532 | **1.30×** |
| n32 合计 ÷ mma3(64) 合计 | 0.611 | 0.864 | **1.41×** |
| n32 合计 ÷ `n_conv8` 合计 | 1.003 | 1.199 | **1.20×** |

落在探针 1.26× 附近 ⇒ **内核这一层确实是 1.26~1.30×**。真计划里最大那条
`Conv.111` 2.98 ms（vs 基线 4.59~5.08）。

端到端用 `ab.sh` 交错（8 轮，40 图，`--tier medium --det-only`）:
**中位 Δdet = −1.95 ms（6/8 轮为负），均值 −3.05 ms**，172 ms 基数上 **≈ 1.1%**。
这个量级与「n32 只是 det 的少数」自洽（n32 设备端 ~8 ms / 形状）。

第一轮曾读到 −15.5 ms，随后逐轮衰减到 −0.3 —— 那是**冷启动瞬态**，不是效应
（同 [[ab-order-effect-swamps-small-gains]]：Δ 幅度衰减而符号不变时先怀疑瞬态）。
日志 `logs/ab_20261010_182514.log`。

## 4. 还剩什么

* 家族里 **64 宽那两条（Conv.121 7.3 ms、Conv.3 3.7 ms）没动**：它是家族的大头，
  但探针已经说明它只有 1.36× 的装载余量，且唯一更低的比值档（0.50）实测崩。
  要动它得换别的方向（不是装载条数）。
* **尾块纯冗余 2.75 ms** 仍未利用——除非找到比 `n_conv8_edge`（1013 GFLOPS）
  更便宜的余数路径，否则不动。
* `n_conv8_mma3` 单条 GFLOPS 已到 2444~2599（纯 MMA 口径），家族天花板附近。
