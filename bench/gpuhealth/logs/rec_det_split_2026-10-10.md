# rec / det 的真实分工（2026-10-10）

起因：此前一直用「rec 占图 58%」这类**剖析占比**排序，而 rec 自己的
FLOP 量是**估出来的**（估成 ~30 GFLOP）。今天用计划转储把 14 份计划按
内核签名分成 det / rec / cls 三组，逐组重算 FLOP，得到与直觉相反的结果。

## 0. 数据来源（都可复现）

- 计划转储 `recplan2_2026-10-10.txt`（**文件名是错的**：它含全部 14 份计划，
  不只是 rec）。分组依据：含 `n_convt4w`/`n_exit` = det；含
  `n_attn_mm`/`n_exit3*` = rec；`entry_out=[N,3,48,192]` 且 104 条 = 方向分类器。
- 真实墙钟 `QPPOCR_GPU_PROF=1`（`rec_wall_2026-10-10.txt`）：det 2 run
  245.1 ms、rec 20 run 277.6 ms（10 行 × 2 趟 ⇒ **det 122.5 / rec 138.8 每趟**）。
- 逐内核剖析 `recblock_2026-10-10.txt`（`QPPOCR_GPU_KERNEL_PROF=30`，全部
  14 份计划各剖一遍，22 个块 = 2 趟）。

**剖析不膨胀**：det 单计划剖析 108.98 ms vs 真实 122.5；rec 两趟剖析
257.06 vs 真实 277.6 ⇒ 剖析值 ≈ 真实值的 0.9 倍。此前「剖析一律膨胀 2×」
的说法作废。

## 2. FLOP 重算（关键更正）

| 阶段 | GFLOP | 墙钟 | GFLOPS | 占 f32 FMA 峰值(3340) |
|---|---|---|---|---|
| det | 136（修正后） | 122 ms | 1115 | 33% |
| **rec** | **~172** | **139 ms** | **1237** | **37%** |

**rec 不是轻量阶段，它和 det 的 FLOP 量基本相等（172 vs 136）。**
此前「rec 只有 ~30 GFLOP、跑在峰值 6%」是估算错误（低估 5 倍），
据此提的「把 10 行 batch 起来填满 GPU」**作废**——rec 每趟 172 GFLOP /
139 ms 已经是 37% 峰值，与 det 同级。

（注：本表用 `2*m*co*taps*cin` 的粗算。det 的 `n_conv8_edge` 是主内核的
M 尾块补集、不是额外工作，粗算会把它重复计一遍，所以 det 从 174 修正到
136；rec 几乎没有 edge 拆分，172 基本就是真值。）

## 3. 逐内核占比（rec 20 块 / det 2 块）

```
det： n_conv8_mma 35.6%  n_conv_dw 22.2%  n_conv8_mma3 12.0%
      n_conv8_mma3_n32 7.1%  n_conv8 6.8%  其余 ≤3.7%
rec： n_conv8_mma 68.1%  n_conv8 12.7%  n_conv_dw 4.5%  n_softmax 4.0%
      其余全部 ≤2.1%
```

**rec 的 `n_softmax` 只有 4.0%** ⇒「softmax→argmax 融合」的账面上限
只有 ~5.6 ms，落地后大概 2~3 ms。rec 的真正重量在卷积。

## 5. 逐节点 GFLOPS（`·` 明细 × 计划形状连接，154 个节点）

宽卷积大多贴着天花板：

```
Conv.54/57  cin768→co1536 m882 grid[14,24]=336  → 2367 / 2297
Conv.28/44/27 cin1024→co512 m1764 grid[28,8]=224 → 2333 / 2341 / 2347
Conv.30/38  cin512→co1024 m1764 grid[28,16]=448  → 2156 / 2309
```

慢的两处：

```
Conv.58  cin1536→co768 m882 grid[14,12]=168 → 1330
Conv.55  cin1536→co768 m882 grid[14,12]=168 → 1954   ← 同形状，差 1.47×
MatMul.12 cin192→co18712 m147 grid[339,1]  → 529    （8 份计划合计 ~8~9 ms）
```

**逐节点 ms 的可信度已验**：同节点在 2 趟里 max/min = **1.00~1.07**（207/229
个节点出现 ≥2 次）。所以 Conv.55/58 的 1.47× 是**真的**，不是噪声。

## 6. 未闭合的疑点（下一步该挖的）

**同一形状、同一网格的两个 `n_conv8_mma` 派发差 1.47×。**
唯一可变的只剩参数块：`b_off`（bias）/ `act`（erf1/SiLU）/ `r_off`（残差）。
即**尾声**。粗算尾声元素数（882×768）与 erf1 的算子数都远不足以解释
0.68 ms，所以要么另有机制，要么粗算漏了什么。

如果查实是尾声 → 单一内核可改，账面 ~20 ms（全图 7.5%）；这是目前
唯一有实测依据、又没归因的大块。

**纪律**：下一步用微基准在**生产内核的真实布局**上搭「同形状 × 开关
act/residual」的对照臂（不许照抄别处接口），且探针只能否证不能拍板。

## 7. 诚实的总账

f32 路径剩下的可挖量：

| 项 | 账面 | 现实 |
|---|---|---|
| rec MMA 1703→2156 | 20 ms | 未归因，机制不明 |
| MatMul.12 → MMA（1.62× 已实测） | ~3.5 ms | 门禁放宽的落地风险 |
| rec softmax→argmax | ~5.6 ms | 落地约 2~3 ms |
| det dw | 24.2 ms | 11 个候选已否证 |
| MMA 族 | 106 ms | **已到自证天花板，关闭** |

**合计约 1.05~1.10×。** 此前报价的 1.25× 站不住：图像 40% 的
`n_conv8_mma` 已经贴着 2209~2467 GFLOPS 的自证天花板，而这台 M4
**没有张量核**（f32 MMA 2204~3326 不超过纯 FMA 峰值 3340，fp16 MMA 1535
反而更低——硬件 fp16 矩阵单元解释不了）。
