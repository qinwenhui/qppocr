# 相位是全局最优吗？—— 两侧都量了，都是 0 最好（2026-10-11）

两条 64 B 对齐修复（`27c0279` 静态、`69a4783` 激活）落地后，**全场的每个段都
落在相位 0**。但"0 最快"只在一个操作数上量过（`n_conv8_mma` 的权重，1.51×，
`conv8_mma_w_sweep` 的 `align` 臂），而修后逐内核的收益幅度**远超**探针预期
（det `n_conv8` 20.82 → 7.45、`n_convt` 7.42 → 0.77）⇒ 幅度是逐内核的、
不能外推。**所以"全 0 未必是全局最优"是个真问题**，必须用生产内核量。

为此给 `Layout` 加了两个实验旋钮（`crates/qppocr-gpu/src/plan.rs`）：

* `QPPOCR_MB_APHASE` —— 把**激活**区整体平移 k 个 word（0..15）；
* `QPPOCR_MB_SPHASE` —— 把**静态**（权重/参数）区整体平移 k 个 word。

均为一次性读入、默认 0 = 现状（默认路径与改动前**逐字节相同**：det 整块
536.4 MB / 静态 62.0 MB，与修复后的记录一致）。每个段的起点仍严格落在
`(16k + 相位)` 上；代价是每次分配多烧 ≤15 word，可忽略。

## 结论

1. **激活侧：平。** 四档合计 99.1 ~ 100.8 ms，逐内核都在噪声内（除下条）。
   唯一有形状的信号是 `n_conv_dw`：**周期 32 B**（0/8 快、4/12 慢，17.20 对
   18.21 = 5.9%），而 **0 已经是其中最快的档** ⇒ 没有可捡的。
   这与 `conv_dw_w_sweep` 的 `QPPOCR_MB_DWMODE=in` 臂同向（它说 +0 最快），
   但幅度对不上（探针 1.61×、端到端这里只有 ~6%）——又一次
   [[probe-wins-dont-transfer-to-production]]。
2. **静态侧：0 明显最好。** 差全部落在 `n_conv8_mma` 上（36.48 vs 38.11~39.94），
   **0 比其余档快 4.5~9.5%**。这条**复现**了探针的结论（相位 0 最快），
   而且是第一次在**真计划**上量到它的幅度。
3. ⇒ **相位这条杠杆已经吃干净。** 「全 0」就是全局最优，剩下的余量不在
   这里；两条修复（静态 16 word 对齐 + 激活 16 word 对齐）都站得住。

## 唯一还看得出结构问题的一处

`n_conv_dw` 的 **9×9 那批跑 10~13 GB/s，比 3×3 那批（60~94 GB/s）低 7 倍**：
`Conv.64` 8.53 ms（107 MB）、`Conv.69` 2.10、`Conv.62` 2.16、`Conv.60` 0.52 …
八条合计 **14.18 ms**（占 det 14%、占全流水线 5.8%）。而 `n_conv_dw_dig`
已量出时间对 tap 条数**近似线性**（`t = 0.181 + 0.0622·taps`），所以
分离式 9×1 + 1×9（18 tap 对 81）是唯一的结构出口，**但要改数值**（两级求和，
非位级一致）⇒ 需拍板。
